# StockOS 整合產品說明書 v1.0
## 自動化公司研究、估值與持續監控系統

- 文件日期：2026-10-21
- 文件性質：目標產品規格／開發與驗收基線草案，不是已上線功能清單。
- 第一個完整應用：NVIDIA（NVDA）。
- 後續方向：相同研究流程與核心引擎，逐步擴展其他公司及估值類型。
- 主要使用者：產品擁有者／自主投資研究者；不以機構多租戶平台作為第一版前提。
- 既有核心：Quarterly Fundamental Valuation Engine（QVE）。使用者提供的 2026-10-09 報告另使用 Quantitative Valuation Engine 名稱；本文件將其視為 StockOS 的研究與估值核心，不因名稱差異推定為不同系統。

> **產品目標：建立一台持續運作的自動研究系統。它會自己取得股價、財務數據、財報與重要線索，判斷公司發生了什麼、哪些因素影響未來獲利，依固定且可驗證的方法計算我們的目標價，持續比較目標價與市場價格，並在重要變化出現時通知使用者。先把 NVIDIA 做完整，再套用到其他公司。**

本文以使用者本次需求為主。既有報告只用來辨識可以承接的資產；未把報告所稱的交付完成等同於本次已獨立查核程式或線上服務。本版新增設計包括目標價期間、排程、發布政策與驗收方式；其中「12 個月目標價」是建議預設，並非已確認的既有實作。

# 第一部分：產品到底要完成什麼

## 1. 一句話定位

**StockOS 是自動運轉的公司研究與估值系統，不只是股票儀表板、新聞摘要器、回測報告，也不是讓 AI 隨意喊目標價的工具。**

使用者加入一家公司並完成一次性設定後，不應每天手動下載財報、複製新聞、更新 Excel、貼 prompt 或執行腳本。這些工作由系統完成；使用者主要看研究結論、追問證據、調整追蹤範圍，並處理少數例外。

系統應持續回答：

| 核心問題 | 應提供的答案 |
|---|---|
| 公司現在怎麼樣？ | 營收、獲利、現金流、財務品質、成長狀態與主要風險。 |
| 最近發生什麼重要變化？ | 新財報、新指引、需求、供應、競爭、政策與重大公司事件。 |
| 這些變化為什麼重要？ | 對營收、利潤、現金流、風險或情境假設的影響與來源證據。 |
| 現在股價是多少？ | 最新可用價格、報價時間、來源、交易時段與延遲狀態。 |
| 我們認為值多少？ | 現在合理價值與具有明確目標日期的系統目標價，附情境區間。 |
| 現價與目標價差多少？ | 價差、估值狀態、資料可靠程度，以及是否值得進一步研究。 |
| 上次之後改了什麼？ | 目標價修訂、主要驅動因素、風險變化與尚未解決的問題。 |

成功不是某一次回測報酬最高，而是上述答案能隨資料更新而自動產生，且可追溯、可重現、可在其他公司重用。

## 2. 使用者拿到的產品

### 2.1 公司主畫面

主畫面先回答「現價、我們的目標價、差多少、為什麼」，不要求使用者先讀技術指標或回測細節。

| 畫面欄位 | 顯示規格 |
|---|---|
| 最新股價 | 最新可用報價；清楚區分盤中、收盤、盤前與盤後。 |
| 現在合理價值 | 用目前資訊評估的當下合理價值，不與未來目標價混用。 |
| 系統目標價 | 本版建議預設為未來 12 個月 Base 目標價；必須顯示目標日期。 |
| 情境範圍 | Bull／Base／Bear；Stress 另列，不假裝是統計信賴區間。 |
| 目標價空間 | 目標價相對現價的百分比差距；不是保證報酬。 |
| 目標價修訂 | 相較上一版上修、下修或不變，以及主要原因。 |
| 公司狀態 | 成長／景氣階段、Forecast Revision、財務品質與核心風險。 |
| 重要線索 | 最重要的新事件、來源、判讀與是否影響估值。 |
| 更新與可靠度 | 股價時間、財務期間、估值時間、資料截止時間、AI 完成狀態與缺項。 |
| 下一步 | 下一個預計追蹤事件、待補資料、是否需要使用者介入。 |

系統目標價是「我們的模型輸出」，不是外部分析師平均目標價。未來若加入市場共識，應另欄顯示並保留其來源與時間，不混成同一欄。

### 2.2 自動交付

日常交付包含公司總覽、重大事件更新、季度研究更新，以及歷史目標價與判斷紀錄。畫面與通知應由同一份已發布 snapshot 產生，不能各自重新要求 AI 寫出不同結論。

一般價格更新只更新畫面。目標價重大修訂、已核實的重要事件、估值區間穿越、資料長時間過期或系統阻塞，才依通知規則提醒。通知需合併重複事件，避免同一則消息多次推送。

### 2.3 不在第一版的範圍

第一版不自動下單，不連接券商執行交易，不承諾獲利或保本。配對套利、槓桿、投資組合最佳化及機構多租戶管理不是完成 NVIDIA 自動研究的前置條件。Opportunity Score 可在內部保留，但不能代替現價、目標價、依據與風險的直接呈現。

# 第二部分：系統怎麼自動工作

## 3. 完整運作流程

```text
公司設定與追蹤清單
        │
        ├── 行情通道：股價／交易時段／公司行動 ───────────────┐
        │                                                  │
        └── 研究通道：財報／公告／法說會／重要事件            │
                         ↓                                  │
                 原文封存、時間標記、去重                    │
                         ↓                                  │
                財務解析與線索證據整理                      │
                         ↓                                  │
          ┌──────────────┴───────────────┐                  │
          │                              │                  │
   Quant：財務、預測、Regime       AI：判讀、風險、挑戰       │
          │                              ↓                  │
          │                       Evidence Gate             │
          │                              ↓                  │
          └──────────────┬── 合格證據與特徵                  │
                         ↓                                  │
            基準估值＋已核准的 Valuation Bridge              │
                         ↓                                  │
              合理價值／目標價／情境／變更原因               │
                         ↓                                  │
                 品質檢查與版本發布                         │
                         └──────────────┬───────────────────┘
                                        ↓
                         現價比較、公司畫面、重要通知
                                        ↓
                              持續監控下一次變化
```

兩條通道分開運作：價格變動不需要重新閱讀整份財報；研究更新也不需要等到股市開盤才開始。財報發布後可以立即建立研究初版，但行情比較必須標明報價是否早於該事件；模擬交易則另外遵守真正可執行的時間政策。

## 4. 自動取得哪些資料

| 資料類別 | 內容 | 主要用途 |
|---|---|---|
| 財務數據 | 損益、資產負債、現金流、股數、分部及補充營運指標。 | 計算歷史表現、預測與估值。 |
| 財報與公司公告 | 法定申報、季度／年度報告、earnings release、重大公告。 | 確認正式事實、風險、會計或業務變化。 |
| 公司指引 | 營收、毛利、費用及其他具有清楚期間與定義的 guidance。 | 更新財務預測並追蹤修訂。 |
| 法說會內容 | prepared remarks、Q&A、發言人與原文段落。 | 判讀原因、限制、管理層說法及未回答的問題。 |
| 行情與公司行動 | 最新報價、歷史行情、拆股、股息及其他影響每股基準的事件。 | 現價比較、報酬評估及價格／股數一致性。 |
| 重要線索 | 客戶、供應商、競爭者、監管機關及可信新聞中的相關事件。 | 發現尚未完整反映在當期財報的變化。 |
| 核准的市場參數 | 估值所需的利率、匯率等資料。 | 按版本化規則更新估值，不由 AI 任意指定。 |

原則上優先取得公司與監管等一手資料；新聞可作為事件發現與補充來源。無法取得官方逐字稿時，明確標示缺失；不能把新聞摘要或 earnings release 冒充完整 Q&A。

數值優先透過結構化資料與確定性解析取得。AI 可以提出抽取候選，但必須通過來源、單位、幣別、期間與會計口徑驗證，才能進正式財務表。GAAP／non-GAAP、季度／累計、weighted-average shares／shares outstanding 不得混用。

資料來源與供應商以 Adapter 介面隔離。提供免費、延遲或付費行情時都必須如實標示；輪詢頻率高不代表上游資料即時。未取得相應資料權限前，不宣稱提供即時全市場行情。

## 5. 什麼叫「重要線索」

重要線索不是所有提到公司的新聞，而是可能改變營收、利潤、現金流、風險、競爭優勢或估值假設的新資訊。

系統先檢查公司關聯性、新穎性、來源可靠性、潛在影響程度與影響期間，再決定只記錄、建立風險提示、更新情境，或觸發重估。同一事件的轉載應聚合，不得因新聞篇數多就重複加分。

### 5.1 NVIDIA 的初始追蹤主題

下列是要監測的類別，不代表正在發生的已確認事實。

| 主題 | 要回答的問題 | 可能連結的模型項目 |
|---|---|---|
| AI 運算需求 | 客戶需求與資本支出是否改變？訓練與推論需求有何差異？ | 營收成長、需求持續性與集中度風險。 |
| 供應與交付 | 封裝、記憶體、產能或產品交付限制是否改變？ | 出貨時程、成長上限、成本與情境風險。 |
| 產品與競爭 | 新產品、替代方案、客戶自研或競爭者進展是否改變定價能力？ | 毛利、成長延續性與競爭風險。 |
| 政策與區域市場 | 官方政策、出口規則或市場准入事件是否影響可服務市場？ | 受影響業務、需求情境與尾部風險。 |
| 財務品質 | 成長是否轉成現金？應收、庫存、股數或資本需求是否異常？ | 現金轉換、每股價值與風險。 |

### 5.2 線索進入估值的規則

**正式數據**在完成驗證後，可按既有模型規則更新預測。**具有證據的質化變化**可更新研究結論、風險與已核准的情境調整。**未確認傳聞、無法量化的推測或互相衝突的說法**應先進觀察／待審區，不直接改變正式目標價。

例如「產能改善」這個句子本身不等於「營收增加某個百分比」。只有已有明確、驗證過的對應規則時，系統才能自動進行數值調整；否則保留為質化線索或敏感度議題。

同時記錄「暫不改目標價」的原因，例如資料尚未確認、已反映在 guidance、影響只在遠期，或現有模型沒有可信量化方法。

# 第三部分：如何判讀與產生目標價

## 6. AI 與財務引擎的分工

| 工作 | 負責者 | 邊界 |
|---|---|---|
| 原始財務數值入庫 | 解析器＋數據驗證 | AI 候選必須經驗證，不得補造缺值。 |
| 財務指標、Forecast、Regime、DCF、multiples | 確定性財務引擎 | 相同輸入與版本，應產生相同數值。 |
| 文字理解、原因、產業線索、風險、挑戰 | AI Analyst | 輸出須連到允許使用的來源，不可自由喊價。 |
| 證據准入 | Evidence Gate＋必要人工審查 | 原文存在不代表推論一定正確，需區分機械與語意驗證。 |
| AI 特徵對估值的影響 | 已核准的 Valuation Bridge | 固定映射、幅度上限、缺值處理及防止重複計入。 |
| 正式發布、研究狀態與通知 | 版本化政策引擎 | 不依 AI 臨時創造交易規則。 |

AI 可以解釋「為什麼」，但正式價格由程式根據已批准的輸入與規則計算。AI 不直接覆寫既有財務 facts、Quant baseline、Regime 或模型參數。核准的 AI 影響應建立獨立情境或 bridge snapshot，保留未調整基準。

## 7. 把「現在合理價值」與「未來目標價」分開

### 7.1 現在合理價值

`F0` 表示在分析時點，以目前可使用的資料與假設估算的每股合理價值。

### 7.2 系統目標價

`T_H` 表示在明確目標日期的每股估值。本版建議 `H = 12 個月` 作預設，並在每份結果記錄 `valuation_at`、`target_at` 與 `horizon`。

12 個月目標價必須由目標日期上的預測財務、估值基準及資本結構推導；不能把當下 DCF 值換個標題就當成 12 個月目標價，也不能把今日價值機械加上一段成長率。股息／分配與目標日之後的現金流需按方法契約處理，避免重複計入。

### 7.3 需要提供的結果

每次正式發布至少包含 Quant baseline、系統 Base、Bull／Bear、獨立 Stress，以及資料完整度與模型限制。情境區間是有條件的估值結果，不是已校準的價格機率區間。Stress 不必作為加權平均的一員。

## 8. 估值流程

### 8.1 基本面與預測

先計算收入成長、毛利、營業利益、現金流、資產負債與每股基準，再產出下一季、未來十二個月及後續年度的預測。保留 Forecast Revision、預測誤差與使用假設。

Regime 用來辨識公司當期的成長／週期狀態，保留 confirmed、candidate、transition 與各類 confidence；不要讓現價上漲本身成為「公司成長更好」的證據。

### 8.2 基準估值與交叉檢查

以公司估值類型預先指定的主方法形成基準，其他方法作交叉檢查。DCF、Forward P/E 或其他倍數不應因數值看起來方便而直接平均；組合政策必須具有方法、權重與適用條件。

Reverse DCF 用來解釋「現價隱含什麼假設」，是市場預期診斷，不應把現價循環灌回獨立合理價值，製造模型追著市價移動的假象。

### 8.3 AI-informed Valuation Bridge

只有准入的特徵才能通過 Bridge。每條映射必須能說明：證據、受影響假設、調整規則、上限、衰減／失效條件，以及與既有 guidance／forecast 的重疊情況。

不得僅因 challenge 數量較多就持續擴大折價；同一根本風險需去重。缺少有效 AI 證據時，輸出沒有 AI 調整的已驗證基準，或標示調整不可用，不得把未知填成中性證據。

既有 Bridge 的權重與 haircut 是需要承接查核的實作，不因此自動成為跨公司的永久標準。[S1：核心模組與演算法實作]

### 8.4 目標價差異解釋

每次修訂要分解為：新財務事實、guidance／forecast revision、Regime、AI 證據與情境調整、市場參數、股數／公司行動，以及時間推進。對同一目標日期的修訂與「目標日往後滾動」必須分開。

## 9. 現價比較與研究結論

當 `P > 0` 且價格與每股估值基準相容時：

```text
目標價上／下行空間 = (T_H / P - 1) × 100%
當下合理價值差距   = (F0 / P - 1) × 100%
```

`P` 是畫面明確標示的可用報價；`T_H` 和 `F0` 不能互換。若幣別、拆股或報價時間不相容，應先對齊或標示不可比較。若要展示包含股息的總報酬，必須另列計算，不能與價格空間混為一談。

第一版的研究結論可顯示「低於估值區間、接近估值區間、高於估值區間、資料不足／待審」。門檻由驗證後的規則決定；大幅價差不自動等於應買入，也不省略模型不確定性。

# 第四部分：自動化、可靠度與操作方式

## 10. 何時更新什麼

| 觸發 | 自動處理 | 是否改變目標價 |
|---|---|---|
| 新報價 | 更新現價、價差、區間穿越狀態。 | 預設否，不因股價漲跌直接修改公司預測。 |
| 新財報／earnings release | 封存、解析、對帳、重算 Forecast／Regime／估值並產生修訂理由。 | 依新資料與模型計算。 |
| 新 guidance | 更新同期間預測、修訂歸因及估值。 | 依正式模型規則。 |
| 法說會稍後到齊 | 補充證據、風險與合格情境調整。 | 視是否形成合格的新影響。 |
| 重大可信事件 | 去重、證據驗證、評估受影響公司與假設。 | 只有已核准映射可自動調整。 |
| 核准的估值市場參數更新 | 更新對應假設並標示原因。 | 可以；需與單純價格變動區分。 |
| 拆股等公司行動 | 對齊價格、EPS、股數及歷史比較基準。 | 純拆股不得被描述為經濟價值上修。 |
| AI／來源暫時不可用 | 退避重試、排隊、保留合格基準並顯示缺項。 | 不憑空生成新調整。 |

### 10.1 建議排程方式

行情按合法資料源可支援的頻率獨立更新；官方公告定期增量檢查，財報窗口提高頻率；重要線索以定期檢索與事件通知並用；每日完成一次資料完整度與服務健康檢查。

實際間隔、允許延遲、發布時限與超時規則寫入設定。來源支援事件推送時可使用，否則輪詢，不假定所有來源都有 webhook。本文件不把既有報告中的 10／15 分鐘情境視為已驗證 SLA。

### 10.2 自動發布與人工介入

**預先核准規則內的日常資料更新、運算與發布自動完成，不要求使用者每季逐筆按確認。** 模型及資料流程的初次驗證、首次正式啟用、模型規則／映射改版、超出映射邊界、關鍵資料衝突或重大證據缺口才進人工審查。

歷史 AI 品質驗收不能被自動化略過；但通過後的日常流程應靠已測試 gate 與異常升級運作，而不是永久把所有更新改成人工作業。

### 10.3 發布狀態

建議區分 `Updating`、`Current`、`Partial`、`Stale` 與 `Blocked`，並另記 AI 是否完成。`Current` 代表符合發布契約與新鮮度，不代表估值必然正確。

發布必須原子化：一份正式結果的財務、預測、估值與來源需相互一致，不得將新財報數字拼上舊目標價卻不標示。重複觸發同一事件不得產生重複正式結果或通知。

## 11. 問題發生時，系統應怎麼做

資料暫時缺失時繼續收集可用項目，保留上一份合格結果但標示過期／待更新；若舊投資假設已被可靠新資訊否定，必須明確撤回或標記不可沿用，不能只顯示舊價格。

AI 額度或 provider 失效不應停止股價更新與既有 Quant 運算。使用既有訂閱與官方 CLI 的策略可以延續，但只有通過資格驗證的 provider 可以產生正式分析；不得讀取或抽取 OAuth token、繞過限制，或因額度不足自行啟用額外付費 API。

服務重啟後從已保存的工作狀態續接；外部取數、分析、發布與通知各有自己的 job 狀態與去重鍵。不可把無限重試當作可靠性，也不可在出錯後默默把 NULL 變成 0。

## 12. 可驗證的研究紀錄

所有正式結果要能回答「這個目標價是用什麼資料、哪個版本、哪些假設算出來的」。保存原文、引文範圍、來源時間、資料雜湊、模型與政策版本、AI 原始輸出、准入結果及發布收據。

公司重新公告、資料更正或 parser 改版應建立新版本；舊版保留，不用新資料靜默回寫歷史。對使用者則呈現新的有效版本與修訂原因，而不是要求讀者自行找出哪份有效。

### 12.1 即時研究與歷史回放分離

即時研究可以透過獨立的資料收集層取得最新資訊，AI 只分析該次允許的證據包。歷史回放只能使用當時 cutoff 前合格的來源，不允許 AI 自行上網補今天的資訊。

`published_at`、`available_at`、`retrieved_at`、`analysis_cutoff` 與 `decision_ready_at` 要區分。歷史重建不能宣稱為當年實際運轉的 live 模型；限制檢索也不能保證模型本身沒有後見知識，因此歷史 AI 結論仍需證據約束與獨立評估。

回測下單時間必須晚於來源可用及訊號完成時間，並符合交易日曆與執行政策。不能無條件假設每一次都來得及用財報後第一個開盤成交。

# 第六部分：從 NVIDIA 擴展到其他公司

## 15. NVIDIA 第一版要做完整的範圍

NVIDIA 第一版需要完成來源連接、股價更新、財務與 guidance 入庫、公司與產業線索監控、AI 判讀、Forecast／Regime、基準與情境目標價、現價比較、修訂通知，以及無人手動啟動的日常運行。

驗證可以從既有代表季度開始，但不能以七個挑選季度代替連續季度研究能力。應逐步覆蓋可取得且符合資料品質要求的連續歷史季度，同時保留真實前瞻運轉紀錄。

主要驗收情境是：**下一份 NVIDIA 財報或重要公告出現時，不用使用者下載檔案或執行腳本，系統會自行處理，最後在畫面上說明最新現價、我們的目標價、變動原因與尚缺資料。**

## 16. 共用引擎與公司設定檔

多公司擴充不應複製整套程式，也不能把 NVIDIA 的成長假設、權重與 valuation multiple 原樣套給其他企業。

共用的部分包括 ingestion、來源時間治理、財務資料模型、證據准入、版本管理、任務執行、估值框架與介面。公司差異由 Company Profile 與 Valuation Archetype 表達。

| 公司設定 | 需要配置的內容 |
|---|---|
| 公司與證券識別 | issuer、ticker、交易所、幣別、證券與上市型態；必要時處理 ADR 換算。 |
| 財務日曆與口徑 | fiscal year、報告期間、會計準則與數值對應。 |
| 資料來源 | 官方申報、IR、法說會、行情及相關事件來源。 |
| 業務結構 | 分部、成長驅動因素、重要營運指標與風險主題。 |
| 估值類型 | AI Compute／Fabless、Foundry、Memory、設備、雲端／軟體等。 |
| 估值政策 | 主方法、交叉檢查、情境映射、限制與品質門檻。 |
| 監控政策 | 關鍵事件、可信來源、更新頻率與通知門檻。 |

新增公司的流程應為「辨識資料 → 產生設定候選 → 驗證／批准 → 歷史與影子運轉測試 → 啟用自動監控」。先用第二家相近估值類型公司驗證可重用性，再擴展差異較大的公司類型；不宣稱換一個 ticker 就自動完成所有估值適配。

## 20. 成功衡量方式

首要衡量自動化程度、資料新鮮度、合格來源覆蓋、可解釋估值發布率、使用者手動介入頻率與錯誤恢復能力。其次衡量 Forecast 準確度、修訂穩定性、AI 證據支持與漏判、情境敏感度及跨公司可重用性。

若評估投資策略，再另外比較同風險／同曝險基準、純 Quant、加入 AI Bridge 的增量、交易成本、現金報酬及樣本限制。不把降低股票曝險造成的低回撤直接宣稱為 AI 的價值，也不以單一 NVIDIA 行情作跨公司有效性的證明。

## C. Job 與狀態模型

建議 job 類型：`DISCOVER_SOURCES`、`INGEST_DOCUMENT`、`PARSE_AND_VALIDATE`、`COLLECT_QUOTES`、`DETECT_EVENTS`、`ANALYZE_EVIDENCE`、`RUN_QUANT`、`RUN_VALUATION`、`CHECK_PUBLICATION`、`PUBLISH`、`NOTIFY`、`RECONCILE`。

狀態：`Queued → Running → Succeeded / RetryableFailed / Blocked / Failed`。模型分析成功不等於發布成功；發布成功也不等於通知已送達。每階段記錄 input/output refs、嘗試次數、錯誤類別與時間。

去重鍵至少綁定公司、來源版本／事件、模型政策版本及有效輸入集合。相同輸入的財務重算應可重現；AI 不承諾完全相同文字，因此保存原始輸出及 cohort，分開衡量數值與語意穩定性。

## D. 最小 API 能力

```text
GET  /companies
GET  /companies/{id}/overview
GET  /companies/{id}/quotes/latest
GET  /companies/{id}/research/latest
GET  /companies/{id}/valuations/history
GET  /companies/{id}/financials
GET  /companies/{id}/events

POST /companies/{id}/refresh
POST /companies/{id}/scenarios

```

人工 refresh 是輔助入口，不是日常更新的必要步驟。寫入類操作應經權限檢查；What-If 與正式發布分離。此處是邏輯接口提案，不是既有可呼叫 API 的聲明。

## E. 運行與成本規則

低成本 parser、來源去重、文字 diff 與事件相關性篩選應先執行，再決定是否使用 LLM。行情刷新、排程、資料庫同步與一般計算不消耗 AI 分析額度。只分析新的或受影響的內容，透過來源與版本 hash 快取。

訂閱 CLI 僅透過官方 subprocess 和既有正式登入使用；記錄 requested／observed model identity，但無法驗證時不得聲稱已確認。未通過資格驗證的替代 provider 不得自行接管正式研究；不足額度時可排隊或以已驗證 Quant 路徑降級。

憑證不可進原文包、LLM context、報告或日誌。來源文字預設為不可信資料，不能指揮模型讀取機密、改變任務或覆寫產品政策。

## F. 發布品質檢查

至少驗證輸入完整性、資料時間、財務口徑、每股價格基準、非有限數／不合理值、DCF 參數相容性、情境順序、Bridge 上限、來源關聯、修訂歸因、AI 證據與發布版本一致性。

低於門檻不等於全系統停止。可以維持行情與資料收集、發布有明確缺項的 Quant-only 版本，或保留舊結果並標示失效；選擇取決於缺項是否破壞當次估值的有效性。

## G. 待實作時綁定的設定

資料供應商、行情延遲／授權、來源檢查間隔、AI provider／配額、重大變化門檻、通知渠道、12 個月目標價詳細方法、Bridge 映射邊界、部署位置與服務目標須在實作時具體綁定。這些尚未確認的值不應被當成現況事實，也不妨礙依現有介面先建立可替換流程。
