僅提醒型預算不會強制封頂；資源大小、留存與更新頻率需要同時限制。新的 spend cap 亦不會停止既有持久 compute/storage 的固定費用，不能當作此 VM 的硬封頂。不得把 NT$1,000 當成 US$1,000，也不能把免費額度當作永久成本承諾。參考 [Google Cloud：預算與提醒](https://docs.cloud.google.com/billing/docs/how-to/budgets)、[spend cap 限制](https://docs.cloud.google.com/billing/docs/how-to/budget-api-spend-cap)。

GCE 舊的 create-with-container／container startup agent 已棄用；採普通 VM 與 systemd 啟動既有 Compose，不新建 GKE、Cloud SQL 或第二套產品。參考 [GCE 容器遷移指引](https://docs.cloud.google.com/compute/docs/containers/migrate-containers)。
